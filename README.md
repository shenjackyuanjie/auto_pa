# Auto_pa

</div>

AppGallery 自动化工具，只有一个 Rust 入口，使用 `search` 和 `hilog` 子命令：

```powershell
cargo run --release -- <子命令> [参数]
```

早先的 Python 实现（`main.py`、`search.py`、`auto_pa.py` 与 `py/`）已经删除，需要查阅旧
代码时用 `git show <commit>:<路径>` 从历史里取。

## 目录结构

```text
src/        Rust 源码
docs/       架构与开发文档
scripts/    真机 UI 调试脚本
.cache/     每台设备的搜索进度（运行期生成）
logs/       日志（运行期生成）
```

## UI 搜索

基于 `hm_driver_rs` 实现的 AppGallery UI 搜索流程：

```powershell
cargo run --release -- search --fresh
```

Rust 默认输出 `INFO` 日志到终端和
`logs/search-rust.log.YYYY-MM-DD`。使用 `-v` 输出 `DEBUG` 日志，使用
`--disable-log-file` 禁用日志文件。

当前待搜索名称完成后，程序会再遍历一次分类，只搜索新发现的名称。每台设备的
进度保存在 `.cache/search/` 下。

可用参数：

| 参数 | 说明 |
| --- | --- |
| `--fresh` | 丢弃已保存的进度，从头开始 |
| `--random` | 只收集新鲜应用，并按随机顺序搜索 |
| `--deep` | 按 `hilog` 的深度遍历分类：走子分类入口并把应用列表滑到底 |
| `--skip-developer` | 跳过「同开发者的应用」收集 |
| `-v` / `--verbose` | 输出 DEBUG 日志 |
| `--disable-log-file` | 不写日志文件 |
| `--hdc-path <路径>` | 指定 HDC 可执行文件路径 |

分类收集的深度有三档：默认只读分类首页固定 3 屏，`--random` 只读「新鲜应用」子页面 3 屏，
`--deep` 走「新鲜应用/新鲜游戏/时下畅销应用/时下畅销游戏」子分类并把每个列表滑到底
（与 `hilog` 一致）。初始遍历只在进度里没有 `collection_complete` 时执行，换深度爬要用
`--fresh` 重新开始。等待子分类或应用列表超时、读到空页面时只记警告并跳过当前层级；
漏掉的名称会在首轮搜索之后的刷新遍历里重爬一遍。

提交搜索时，纯英文名称先按回车，其余情况点击「搜索」按钮。部分平板按回车会直接
跳转搜索结果页，此时搜索框的 key 从 `__SearchField__search_box*` 变成
`__SearchField__searchFrameInput*`，浮层里的「搜索」按钮随之消失；这种情况下按钮
缺失属于正常现象，程序以搜索结果页是否出现作为唯一判据，不再把按钮当作必需条件。

### 同开发者的应用

搜索成功后，程序会点击搜索结果里的第一个应用进入其详情页，向下滚动找到
「同开发者的应用」区块。该区块一次最多展示三行三列：没填满时它就是该开发者的全部应用，
直接读取区块里的名称；填满时才点区块最右侧的「更多」进入同名列表页并划到底。收集到的
名称会并入待搜索名称，并在下一轮刷新遍历后继续搜索：

```text
搜索结果页 -> 第一个应用详情页 -> 下滑找到「同开发者的应用」
           -> 区块没填满：直接读取区块内的名称
           -> 区块填满：点「更多」-> 开发者应用列表页划到底
           -> 原路返回搜索结果页
```

详情页没有这个区块（例如开发者没有其他上架应用）时跳过当前应用；偶发失败只记录警告并
恢复搜索结果页，不会让本次搜索失败。使用 `--skip-developer` 可以完全关闭这一步。

同一个开发者往往有多个应用被搜到，而「下滑找区块 + 进更多列表页划到底」是整轮搜索里最
贵的一步：详情页一打开就先读头部的开发者名（不用滚动），本轮已经收过这个开发者就只退回
搜索结果页直接跳过。这份名单在每轮分类遍历开始时清空，所以刷新遍历之后会重新收集一遍。

## UI 分类遍历

`hilog` 子命令只做 UI 遍历：它会在每台在线设备上启动
AppGallery，遍历「应用」和「游戏」的分类页面，并将每个应用列表下滑至稳定。
默认不抓取 hilog，也不提交应用：

```powershell
cargo run --release -- hilog
```

可用参数包括 `--skip-categories <名称>...`、`--loop <次数>`、
`--loop-wait 5m`、`--ping 15` 和 `--keep-open-on-error`。`--submit`
为未来的 hilog 抓取和应用投稿流程预留；当前版本会明确拒绝该参数，避免悄悄执行
不完整的投稿流程。

偶发情况（等待分类内容或应用列表超时、当前页面没有应用卡片）只记录 warning 并跳过
当前分类，不会让整台设备失败。只有结构性失败（找不到分类列表、滚动次数超过上限）
仍会报错。
